# わりかんメモ v0.13

旅行・合宿・飲み会などの立て替えを記録し、「誰が誰にいくら払えば精算できるか」を最小の送金回数で出す Web アプリ。アカウント登録なし。

- 公開URL（GitHub Pages）：https://tabearyoshi-hash.github.io/warikan-memo/
- リポジトリ（公開）：https://github.com/tabearyoshi-hash/warikan-memo （2026-11-12 ユーザー決定で公開＋Pages。v0.12 を Web UI アップロードで反映済み）

## 使い方
1. イベントを作る（「新しいイベント」ボタンで追加、セレクトで切り替え）。
2. イベント名を入力（任意）。メンバーを追加する。名前を間違えたら、メンバー一覧の「変更」で直せる（支出・「自分」・支払い済み印も一緒に新名前に変わる）。「自分は」で自分を選ぶと、精算で自分の行だけ目立って表示され、自分の支払い／受け取りのまとめも出る（イベントごとに保存）。
3. 支出を追加する：内容・支払った人・金額・対象者（割り勘する人だけにチェック）を入力。金額と対象者を選ぶと、記録する前に「1人あたり」の金額が表示される（端数設定で丸めた金額）。金額は全角数字（１２００）・カンマ（1,200）・「円」付き（1200円）でも入力できる（貼り付けた金額もそのまま使える）。金額を間違えたら、支出一覧の「編集」で直せる（消して入れ直す必要はない）。支出を記録すると、支出一覧に記録した日時（「11/13 03:05」の形）が表示される。編集しても記録日時は変わらない。
4. 「精算」にメンバーごとの残高と送金リストが自動表示される。送金が済んだら「支払い済みにする」を押すと、残り件数・残額と支払い済み一覧が表示される（間違えたら「取り消す」で戻せる）。「精算まとめをコピー」で送金リストをテキストでコピーでき、LINEなどに貼り付けて全員へ送れる（支払い済みの送金には「（支払い済み）」が付き、最後に残額または「全て支払い済みです」が出る）。
5. 不要になったイベントは「このイベントを削除」で消せる（確認あり、最後の1件を消すと空のイベントが1件残る）。
6. 端数の扱いは画面下部の「設定」で変えられる：単位（1円・10円・100円）と、切り上げ／切り捨て／四捨五入を選べる。標準は1円単位・切り上げ。設定はイベントごとに保存される。

## ルール
- イベントごとにメンバーと支出が分かれる。切り替えても他のイベントのデータは残る。
- 1件の支出は対象者で均等割りする。1人あたりは下部の「設定」の単位（1円・10円・100円）と切り上げ／切り捨て／四捨五入で丸める（標準は1円単位・切り上げ、2026-11-12 ユーザー決定。単位も選択式、四捨五入は同日追加で単位の半分以上は切り上げ・未満は切り捨て）。全員の丸め額は同じだが、丸めで出た差額はその支出の支払者が引き受けるよう支払者の負担を差額分だけ調整するため、残高の合計は常に0になり、送金リストで全員が精算完了になる。例：1,000円を3人・100円単位・切り上げなら、他の2人は400円ずつ払い、支払者の実質負担は200円になる。残高一覧では支払者の負担だけ差額分ずれて表示される。支出フォームの「1人あたり」プレビューは丸め額そのものを表示する（記録前の確認用で、保存されるのは支出だけ）。端数設定がない旧来の純粋関数呼び出しでは、従来の「端数を1円ずつ配る」計算が互換として残っている。
- 送金リストは貪欲法で作り、送金回数は「メンバー数−1」以下に収まる。
- 支出に使われているメンバーは削除できない（先にその支出を削除すること）。名前の誤字はメンバー一覧の「変更」で直せる。改名すると支出の支払者・対象者・「自分」の指定・支払い済み印の送金元／送金先も一緒に置き換わる。送金内容（金額）は変わらないため、支払い済み印はキーを書き換えて残る（支出の追加・削除で印が落ちる扱いとは違う）。空・同じ名前・すでにいる名前への変更はできない。
- データはブラウザの localStorage に保存する。保存できない環境では警告バナーが出るが、画面操作は止まらない。
- JSON 書き出しは現在表示中のイベントだけを出す。JSON 読み込みは上書きではなく、新しいイベントとして追加する。
- v0.1 の単一イベントの保存データは、初回に自動で1イベントとして移行される。
- 支払い済み印はイベントごとに保存され、切り替えても残る。送金は「送金元・送金先・金額」で識別するため、支出の追加・削除で送金内容が変わると、一致しなくなった印は落とされる（金額が変わった送金を済んだままにしないための安全側の扱い）。残高一覧は支払い済み印では変わらない（送金が済んだ印であり、立て替えの記録自体は残る）。
- 支払い済み印は JSON 書き出し／読み込みでも引き継がれる（旧JSONには無いので空になる）。
- 「自分」はイベントごとに保存され、切り替えても残る。JSON 書き出し／読み込みでも引き継がれる（旧JSONには無いので空になる）。「自分」に選んだメンバーを削除すると、「自分」の指定は外れる。
- 支出一覧の「編集」で、内容・支払者・金額・対象者・メモを直せる。編集しても支出の識別子は変わらない。記録した日時も編集では変わらない（記録した日時のまま）。「更新する」で保存し、「編集をやめる」で編集をやめられる（支出自体は変わらない）。編集中にイベントを切り替えると編集状態は外れ、フォームは空になる。編集で送金内容が変わると、一致しなくなった支払い済み印は落とされる（追加・削除と同じ安全側の扱い）。
- 支出の記録日時（createdAt）は、記録したときに自動で付く。メンバー名の変更・JSON書き出し／読み込みでも引き継がれる（旧JSONには日時がないので、その支出は日時を表示しない）。
- 「精算まとめをコピー」は画面の送金リストと同じ内容・同じ端数ルールで文面を作る（純粋関数 settlementText）。コピーに失敗した環境では代替手段（textarea＋execCommand）を試し、それも駄目なら理由を表示する。データが変わると「コピーしました」の表示は消える（古い文面が残らない）。
